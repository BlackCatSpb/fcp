# Long-Term Memory for MemBind (Concept)

**Цель**: добавить механизм накопления знаний между сессиями, не нарушая парадигму архитектуры (no softmax, no sigmoid gates, no attention).

## Иерархия памяти

```
                    τ        объём    обновление
Рабочая память     ~8 tok    r²×H    каждый токен (covariance scan)
Сессионная память   ∞        r²×H    финал сессии → SVD → resid
Долгая память       ∞        R×D     накопление resid через τₛ сессий
```

## 1. Сессионная память (Cov → resid)

После каждой сессии (разговора, батча):
1. Берём `M_final` — финальное состояние covariance из каждого слоя. Форма: `(H, r, r)`.
2. SVD: `M_final ≈ U · S · Vᵀ`, берём top-1 вектор (самая сильная компонента):
   - `u, s, v` — форма `(H, r, 1)`, `(H,)`, `(H, 1, r)`
3. Это **residual-пара** `(p, q)`:
   - `p = u · √s` — читающий вектор
   - `q = v · √s` — записывающий вектор
4. Дополняем bind-проекцию аддитивно:
   ```
   h_adapt = h_norm + (u * (v + mem_sum + p@q·h_norm)) @ W_out
   ```
   где `p@q·h_norm = q^T · (p^T · h_norm)`. Это bilinear bind — архитектурно чистый приём.

**Без изменения архитектуры**: мы не добавляем параметры, а только модулируем существующий `W_out` через bilinear resid.

## 2. Долгая память (Resid → Adapter)

Сессионные `(p, q)` не хранятся вечно — они накапливаются через **скользящую SVD-агрегацию**:

```
P_buffer = [p_1, p_2, ..., p_{τₛ}]   — FIFO буфер на τₛ сессий
Q_buffer = [q_1, q_2, ..., q_{τₛ}]

Каждые τₛ сессий:
  P_stack = stack(P_buffer)  → SVD → top-R компонент → A (H, r, R)
  Q_stack = stack(Q_buffer)  → SVD → top-R компонент → B (H, r, R)
```

Эти `A, B` — **адаптеры**, которые встраиваются как учимый параметр (или как буфер):

```python
# В MemBindBlock — дополнительный член в bind-выходе:
mem_long = (h_norm @ A) @ B.T  # bilinear, O(D·r·R), R=2–4
h_adapt = h_norm + (u * (v + mem_sum + mem_long)) @ W_out
```

**R = 2–4** → 2×896×4 ≈ 7K параметров на слой, ~170K на 24 слоя.

## 3. Отличие от LoRA

| | LoRA | MemBind Long Memory |
|---|---|---|
| Куда | Q/K/V проекции | Bind-выход (W_out) |
| Агрегация | SGD | Cov → SVD → агрегация |
| Зачем | fine-tune веса | кодировать "что было в сессиях" |
| Обновление | backprop | forward-pass + декомпозиция |

Мы не заменяем fine-tune. Мы добавляем **билайнерный след сессии** поверх существующего W_out. Он не требует backprop для записи — только для чтения во время forward pass.

## 4. Двухслойная память в forward

```python
# Рабочая память (cov scan) — уже есть
mem_sum = read_covariance(Q, M_all, W_read)

# Сессионный resid (последняя сессия)
if self.session_p is not None:
    p, q = self.session_p, self.session_q
    mem_session = (h_norm @ p) @ q.T  # (B, L, D)

# Долгий адаптер
mem_long = (h_norm @ A) @ B.T

# Сумма
v_enh = v + (mem_sum + mem_session + mem_long) @ W_mem2v  # × ? — это уже детали

# Bind
h_adapt = h_norm + (u * v_enh) @ W_out
```

## 5. Цикл обучения на ходу

```
Пользователь → диалог (N токенов)
  → cov_state запоминает паттерны (τ ≈ 8)
  → конец диалога: M_final → SVD → (p, q)
  → (p, q) → P/Q_buffer
  → каждые τₛ сессий: SVD(P_buffer) → A, SVD(Q_buffer) → B (обновление адаптера)
```

Запись: O(H·r² + H·r·τₛ·R) — пренебрежимо.
Чтение: O(D·r·R) — 4 дополнительных matmul на слой.

## 6. Когда внедрять

После масштабирования до PPL < 50 и стабилизации основной архитектуры. Сейчас модель не знает ни языка, ни фактов — нечего накапливать в долгой памяти.
